## 7. 제약 조건 — 전 단계에 걸리는 전제

1. **Humanoid 리그** (`Humanoid_F.fbx`, `animationType: 3`, `optimizeGameObjects: 0`)
   → 리타게팅은 되지만 팩마다 골격 비율이 달라 **포즈 오차가 남는다.** P2에서 클립을 조달할 때 **CombatGirl 팩(실제 스킨 메시 소속)을 기준 팩으로 고정**할 것.
   → Animator가 **모델 루트가 아니라 그 부모**에 붙어 있다(`PlayerCharacter` → `CombatGirls_Sword_Shield`). Humanoid라 동작하지만, IK(P1-6/7) 작업 시 본 계층이 한 단계 어긋난 배치임을 전제해야 한다.

2. **Root Motion OFF** (`PlayerCharacter.prefab:85`) — 이동은 100% `Rigidbody.linearVelocity` 물리 구동.
   → **스트라이드 동기화가 원리적으로 보장되지 않는다.** P1-8(timeScale 매칭) + P1-6(Foot IK)이 현실적 최선이고, P3-5(Root Motion 도입)는 물리 구동 전면 재작성이라 **권장하지 않는다.**
   → `localScale 0.9` · `baseMoveSpeed 5` / `baseRunSpeed 8` 에 맞춰 리타게팅·스케일링된 클립이 **하나도 없다** — P1-8 계산 시 스케일 반영 필수.

3. **이질 소스 3팩 혼합** (CLazy / GhostSamurai / CombatGirl)
   → 무기 없음: Idle 60F / Walk 28F / Run 16F 전부 CLazy이나 **프레임 수가 3.75배 차이**.
   → 무기 장착: Idle·Walk = GhostSamurai / Run = CombatGirl **2개 팩 혼합**.
   → 특히 `APose_Idle` 어드레서블이 가리키는 FBX에는 클립이 1개뿐이고 **이름이 `HeavyCharge`** — **평상시 idle과 강공격 차지 자세가 같은 클립**이다. (P1-10이 이걸 1줄로 고친다)

4. **무기별 로코모션 매핑 누락 — 구조 문제**
   → **Bow / Crossbow AnimSet에는 로코모션 매핑이 아예 없다.** 활을 들면 CLazy 기본 로코모션으로 되돌아가 무기별 자세가 불일치한다. P1-9(임시) → P2-11(정식) 2단계로 처리.
   → `AnimatorOverrideService.Override(key, …)`의 key는 **원본 "클립 이름"**인데 AnimSet은 `baseClipName`(= 상태 이름)을 넘긴다. **둘이 우연히 일치하는 항목만 성공**한다 — 이 설계가 22건 결손의 구조적 원인이다. P0-(a)에서 반환값 경고를 넣지 않으면 **앞으로 추가되는 매핑도 계속 조용히 실패**한다.

5. **씬·에셋 조작 규칙** (CLAUDE.md)
   → 컨트롤러/프리팹 수정은 **Unity MCP 경유**. `.meta` 직접 생성·수정 금지(단 P0-13의 `loopTime`은 FBX 임포터 설정이므로 **Unity 인스펙터에서 변경**할 것).
   → 새 상태 추가 시 `writeDefaultValues = false` (P0-12와 동일 방침).
   → `.cs` 수정 후 `refresh_unity` → `read_console`로 컴파일 에러 0 확인.
