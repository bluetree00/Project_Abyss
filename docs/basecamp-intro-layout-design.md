## 1. 시나리오

서임을 받는 순간 스러진 기사. 멀린(연출상 `???`)이 그를 불러, 어떤 검이 될지 정해지지 않은 **미완의 검(무형검)** 을 쥐어준다.
검을 받고 → 곁에 둘 원거리를 고르고 → 유물(정체)을 선택하고 → 시험한 뒤 → 심연으로 떠난다.

## 2. 공간 문법 — 폭이 곧 연출

| 폭 | 의미 |
|---|---|
| **좁힘 7m** | 시야에 제단 말고 들어올 게 없다. 선택이 무거워진다. 의식(儀式)의 구간. |
| **열림 21m** | 유물을 고르는 순간 통로가 벌어진다. 넓어지는 것 자체가 연출 — 미완에서 완성으로. |
| **넓힘 35m** | 휘두르고 구를 자유. 더미로 시험하고 게이트를 마주본다. 행동의 구간. |

폭이 **7 → 21 → 35** 로 두 번 열린다. 한 번에 벌리지 않고 계단식으로 여는 편이 "세계가 계속 열린다"로 읽힌다.

## 5. 발견된 이상 4건 (작업 중 함께 정리)

1. **`NaveFloor_96_9 (1)`** — 이름이 96열인데 실제 `x103.51`, **scaleX 1.0252**로 늘어남. 다른 타일은 전부 `x*.476` / scale 1.
   → `NaveFloor_103_9`로 개명 + `x103.476` + scale 1 복원.
2. **바닥 4장이 레이어 `Default`** (`68_9`, `68_16`, `68_23`, `75_16`) — 나머지는 `Ground`.
   → **플레이어 접지·레이캐스트가 Ground 마스크를 쓰면 이 타일 위에서 오작동**한다. `Ground`로 통일.
3. **`Rail_E_16 (1)/(2)`가 `y8.5`** — 나머지 난간은 전부 `y10.5`. 2m 낮게 묻혀 있다.
   → `y10.5` 정렬 + `Rail_E_27` / `Rail_E_13`으로 개명.
4. **스테이션이 한 덩어리가 아님** — 조명만 받침대 자식이고 **제단은 받침대와 형제**. 이동 시 둘을 각각 옮겨야 어긋나지 않는다.
   → 선택: 제단을 받침대 자식으로 부모화(제단이 획득 시 자기를 Destroy 해도 부모·조명은 남으므로 안전). 단 `Pedestal_Forge`는 scale 0.7이라 부모화 시 스케일 보정 필요.

## 7. 작업 순서 (의존 관계)

1. **이상 정리** (§5) — 레이어 통일, `96_9 (1)` 복원, 동쪽 난간 y정렬·개명. *다른 작업과 독립, 먼저 해두면 이후 검증이 쉬움.*
2. **바닥 6장 이동** (§6.1) → 통로 7m 성형 + 시험장 35m 확장이 동시에 완성됨.

5. **트리거·배선** (§6.4) + 디렉터 `steps` 순서 정리(원거리→유물).
6. **정리** — 여분 받침대 처리, 무형검 비주얼 배치, 씬 저장.

## 8. 이미 구현·검증된 것 (2026-07-19, 컴파일 0 에러)

### 획득 순서 독립성
무형검·원거리·유물을 **어떤 순서로 얻어도 결과 동일**하도록 3경로를 고정 슬롯화.

| 경로 | 처리 |
|---|---|
| `WorldSwordAwakening` | 무형검 → **항상 Slot0 활성** |
| `WeaponForgeAltar` | 원거리 → **항상 Slot1 비활성**. `if(WeaponSlot0!=null) Switch` 상호참조 제거 |
| `BaseCampBootstrapper.EquipLoadoutWeaponsAsync` | 유물 재스폰 시 고정슬롯 복원(자동 빈슬롯 배정 폐기) |

신규 API: `PlayerWeaponManager.AcquireWeaponToSlotAsync(data, slot, setActive)`,
`GameRunBootstrapper.EquipWeaponToPlayerAsync(so, player, slotIndex, setActive)`. 기존 자동배정 경로는 보존.

> 수정 전 버그: `AcquireWeaponAsync`가 `GetFirstEmptySlotIndex()`로 배정해서 **원거리를 먼저 얻으면 원거리가 Slot0**에 들어가고 무형검이 Slot1로 밀렸다(E/R 스킬이 원거리에 붙음).

### 게이트 = 유일한 관문 (하데스식)
- 중간 배리어 **전부 없음**(`Dome_Gate` 제거됨).
- 게이트는 **항상 활성**, 상시 폴링 없이 **충돌 시점에만** `IsLoadoutReady()` 검사.
- 전제조건 = **유물 + 무형검**. 원거리는 **선택**이라 제외.
- 미달 시 부족분 + 획득 위치를 `HudPresenter.ShowBuffNotice`로 안내(쿨다운 3초).

> 근거: 하데스는 무기를 "출발 전제조건" 한 곳에서만 강제하고 보온은 스킵 가능. 우리는 유물·장비를 런 중 보충할 수 없으므로 그 안전망을 게이트 검사가 대신한다.

## 9. 카메라 · 이동 · 대시 (2026-07-21, 컴파일 0 에러)

### 구역별 카메라 — `CameraZone` (신규, 구형 2종 흡수)
`NaveProcessionalTrigger`(오빗 전용)와 `CameraHeadingZone`(heading 전용)을 하나로 통합. 두 구형 오브젝트는 **비활성**(삭제 아님).

- **릴레이가 기본** — 이탈해도 해제하지 않고 다음 구역이 덮어쓴다. 되돌아가거나 옆으로 벗어나도 카메라가 안 튄다.
- **구간을 이어붙여 배치**(겹침·빈틈 0) → 어느 순간에도 구역이 하나뿐 → 우선순위 로직 불필요.
- 진행축 방향으로 **12~32m** — 대시(약 20m/s, 물리 스텝당 0.4m)로 통과해도 트리거 누락 없음.
- `restoreOnExit`(오빗 복귀) / `restoreHeadingOnBackExit`(역방향 이탈 시 시선각 복귀) / `firstRunOnly`·`repeatRunOnly` 플래그.

| 구역 | X | 오빗 | heading |
|---|---|---|---|
| `CamZone_0_PreStair` | 7~16 | — | **0↔90 전환 + 역방향 복귀** (계단 앞 평지) |
| `CamZone_1_Entrance` | 28~40 | 기본 | — |
| `CamZone_2_Colonnade` | 40~72 | 낮은 시점(2.5/13) | — |
| `CamZone_3_Corridor` | 72~96 | 기본 | — |
| `CamZone_4_Arena` | 96~121 | 약간 높게(9/5.5) | — |

> 축 전환은 지형이 꺾이기 때문에 필요하다: 내부(스폰~계단)는 **Z축 진행**, 성당 나브는 **X축 진행**.
> `CamBlend_StairAscent`(진행률 비율로 연속 회전)도 만들었으나 **계단에서 호버 스프링의 상하 출렁임이 각도로 증폭돼 떨림** → 폐기(비활성). 대신 계단 **앞 평지**에서 1회 전환.

### 이동 기준 = 카메라 heading (회귀 없음)
- `PlayerController.CheckMovementInput`을 월드축 고정 → **카메라 heading 상대**로 전환. heading 0이면 결과가 수식적으로 동일 → 던전 등 기존 구간 무변경.
- **입력 유지 중 기준 고정** — 카메라가 연출로 회전하는 동안 매 프레임 최신 각도를 쓰면 누르고 있는 방향이 휩쓸린다. 입력을 놓거나 방향을 바꿀 때만 현재 카메라 기준으로 다시 잡아, 회전 중에도 일관된 월드 방향으로 이동한다.

### 온보딩 연출 시점 = 현재 heading 기준 (회전 고정 해소)
`PlayOnboardingRevealAsync`의 `viewOffset`을 **월드 고정 → 현재 카메라 heading으로 회전**. 이전엔 항상 월드 −Z 뒤에서만 찍혀 접근 방향과 무관하게 각도가 고정됐다.

### 대시 램프 발사 — 2겹 차단
경사/계단을 고속으로 타면 호버 스프링(지면이 급히 솟아 error 급증) + 콜라이더 반발이 겹쳐 위로 발사됐다. 1차 수정(접지 분기 내 속도 클램프)은 **발사 순간 접지가 풀려 그 분기를 안 타서** 무력. 2겹으로 재수정:
- `LocoDodgeState` — **대시 중 상승 속도 상한 3m/s**(접지 무관, 매 프레임 덮어쓰므로 확실 차단).
- `DefaultJumpAbility` — **스프링 출력 상한**(중력 상쇄 + 추가 상승 가속 25m/s²). 달리기로 언덕 진입 등도 커버.

## 10. 온보딩·퀘스트 정합성 점검 (2026-07-21)

**연출 디렉터**(`BaseCampOnboardingDirector`, 카테고리 문자열로 진행)와 **퀘스트 DB**(`QuestManager` + tut_* SO 체인)가 **별개 시스템**이라 여러 곳이 어긋나 있다.

| 심각도 | 문제 |
|---|---|
| 🔴 | **무형검 각성이 퀘스트 체인에 없음**. DB 체인은 `유물→장비→게이트→서약`. QuestTestFlow 첫 등록도 `tut_acquire_relic`(유물)이라 HUD 목표와 강제 순서가 어긋난다. |
| 🔴 | **순서 불일치**. 디렉터 steps는 씬 배치에 맞춰 `장비→유물`인데 DB 체인은 `유물→장비`. |
| 🟠 | 디렉터가 카테고리 문자열(`SwordAwaken/Equip/Relic`)로만 진행 — 퀘스트 완료·대사·다음 등록은 QuestManager가 별도로. **한쪽만 고치면 어긋나는 이중 구조**. `SwordAwaken`은 퀘스트 카테고리로 등록조차 안 됨. |
| 🟠 | `tut_covenant`(서약)가 체인 끝에 남음 — 서약은 BaseCamp 폐기·심연 이동. 완료 불가 퀘스트가 로그에 잔류. |
| 🟡 | `QuestTestFlow.firstQuestCode` 하드코딩 — 첫 퀘스트가 디렉터·씬·DB·이 코드 **4곳에 분산**. |
| 🟡 | `ShowGuideline`이 버프 알림창(`HudPresenter.ShowBuffNotice`)으로 나감 — 초회 서사 대사 미출력(주석에도 "임시"). |

**근본 원인**: 무형검 도입·순서 변경이 디렉터에만 반영되고 퀘스트 DB엔 반영 안 됨.

**고칠 방향** (미착수): ① `tut_awaken_sword` 신설(카테고리 SwordAwaken, 체인 맨 앞) + `firstQuestCode` 교체 ② 체인 `무형검→장비→유물→게이트`로 재정렬 ③ 서약 퀘스트 제거/이동 ④ (선택) 디렉터가 퀘스트 체인을 직접 읽어 이중 구조 제거.
