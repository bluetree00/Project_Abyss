# Ch1 Forest 수직슬라이스 설계

> 목표: **한 챕터(Ch1)를 처음부터 끝까지** 공간·빛·프롭·외형까지 입혀
> "챕터마다 다른 곳에 왔다"는 체감을 만드는 파일럿. 여기서 만든 틀을 Ch2~4로 복제·변주한다.

## 0. 왜 지금 챕터가 다 똑같이 느껴지나 (확정 진단)

1. **방 골격 35개가 전 챕터 100% 동일** — 벽·문 배치가 바이트 단위로 일치. 32×32 빈 직사각형 + 2×2 벽덩어리 2개. 다른 건 스포너 토큰뿐.
2. **미사용 토큰** — `O`(장애물)·`.`(구멍)·`Pt`(낙사)·`d*`(장식)·`C`·`R`·`D`가 CSV에서 전부 0회. 방이 바닥+벽+몹뿐.
3. **로컬 조명 0개** — 팔레트 `lighting` 미직렬화로 `BuildRoomLights`가 항상 즉시 리턴.
4. **수직성 전역 고정** — `wallLayers=12`가 부트스트래퍼 전역. 전 챕터 같은 높이·같은 천장(바닥 뒤집기).
5. **외형** — 전부 Unity Cube에 머티리얼만. (Forest 자연물은 GUID 유실로 깨져 있었음 → 복구 완료)

→ 결론: **챕터 차별화의 본체는 에셋이 아니라 "공간 문법 + 빛 + 수직성"이다.** 에셋은 그 위에 얹는 마감.

## 1. 범위

- **파일럿 대상**: Ch1. Ch1은 난이도에 따라 **Forest(전반) → Abyss(후반) 2막**이므로, 이 슬라이스는 두 테마를 다 만진다.
  - **1차**: Forest 테마 방 (숲·열린 하늘)
  - **2차(연속)**: Abyss 테마 방 (심연·구멍·부유 발판) — 같은 프레임워크에 다른 에셋/문법.
- **비대상(이번 슬라이스 밖)**: Ch2~4 재저작, 커스텀 아레나(보스/상점 손맵), 모듈러 던전 킷 도입.
- **성공 기준**: Ch1을 한 판 플레이했을 때 (a) 초반 숲과 후반 심연이 명확히 다르고, (b) 방마다 형태가 달라 "같은 방 반복" 느낌이 없고, (c) 빛·프롭으로 분위기가 서는 것. 회색 Cube 상자 0개.

## 2. 네 개의 레버 — 설계

### A. 공간 문법 (방 골격 재저작) — **효과 최대, 코드 변경 0**

방 풀 CSV(`CHAPTER_1_ROOM_POOL.csv`)의 `grid_csv`를 테마 성격에 맞게 다시 짠다. **새 시스템·코드 불필요** — 이미 있는 토큰을 쓰기만 하면 된다.

**Forest 방 문법** (열림·유기적·시야 차단):
- 외곽을 직사각형이 아니라 **들쭉날쭉하게** (벽 라인을 ±2~3셀 물결). `W`로 경계, 안쪽은 `F`.
- `O`(장애물=바위/나무)를 **군락으로** 흩어 시야·동선 차단. 2~4개씩 뭉치게.
- `d*` 장식(나무·덤불·버섯·꽃)을 통행 가능 바닥 위에 뿌림 — 밀도로 "숲" 표현.
- 개활지(전투 공간)와 수풀(이동 공간)의 리듬.

**Abyss 방 문법** (수직·위험·부유):
- `.`(Empty=구멍)로 바닥에 **균열/심연**을 내고, `Pt`(낙사 트리거)로 실제 낙사 위험.
- 발판 사이 점프 동선. 벽은 낮거나 없음(허공).
- 장식 최소, 대신 빛(아래에서 올라오는 발광)으로 분위기.

**작업 물량**: Forest 방 ~8종, Abyss 방 ~8종 신규 저작(현재 골격 재사용 금지). 린터(`Tools/RelicFairy/Validate Room CSVs`)로 검증.

> ⚠️ 저작 후 **뒤끝 CDN 재업로드 필수** — 런타임은 CDN 우선. (미완 상태면 온라인 실행에 반영 안 됨)

---

### B. 벽 & 수직성 — **새 구조 필요 (아래 대안 검토)**

**문제**: `wallLayers=12`가 `GameRunBootstrapper` 전역이라 모든 챕터가 같은 벽 높이·천장.
게다가 벽 프리팹 처리 방식이 두 갈래로 갈리는데 코드는 한 가지만 안다:
- **스택형**(현재 Cube): 1m 프리팹을 `wallLayers`번 수직 반복. `Block_Wall_Forest`는 scale (1,3,1)에 12층 스택 → 과한 중첩·낭비.
- **단일형**(절벽): `Block_Wall_Forest_Cliff`는 scale 0.3, 콜라이더 3.5×5m = **셀 하나에 안 들어가는 단일 요소**. 스택하면 안 됨. ← 12층 모델과 근본 비호환.

Forest는 "벽=절벽(단일형) + 천장 없음(열린 하늘)", Abyss는 "벽 낮음/없음"이 필요 → **수직 프로필을 팔레트 단위로 내려야 한다.**

#### 대안 비교 (구조 설계 규칙에 따른 검토)

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **A. 팔레트가 수직 프로필 소유 (추천)** | `BlockPalette`에 `wallHeight`·`wallMode(Stacked/Single)`·`hasCeiling` 추가. 부트스트래퍼는 전역 대신 `palette.VerticalProfile`을 읽음. 전역 `wallLayers`는 폴백 기본값. | **조명이 이미 팔레트에 사는 것과 일관**. 방 테마→팔레트가 곧 외형 단위. 추가 에셋/파일 0. | `BlockPalette` 필드 증가. 6개 팔레트 .asset 재저장 필요. |
| B. 별도 `WallStyleSO` 신설 | 벽 처리 규칙을 SO로 빼고 팔레트가 참조 | 벽 로직 분리 | 한 줌 필드에 SO 신설 = 과한 추상화. 파일·배선 증가. |
| C. 전역 유지 + 팔레트 옵션 오버라이드 | `wallLayers` 전역 그대로, 팔레트에 nullable 오버라이드만 | 최소 변경 | 진실의 출처가 두 곳으로 갈림. "왜 어떤 건 전역 어떤 건 팔레트?" 혼란. |

**→ 채택: 안 A.** 근거: `RoomLightingConfig`가 이미 팔레트에 직렬화돼 있음(같은 자리에 수직 프로필도 두는 게 자연스럽다). 벽 모드는 `MapBuilder.Build`에서 분기:
- `Stacked`: 현행 로직(`wallHeight`번 반복). 실내 던전(Ch2~4 예정)용.
- `Single`: 셀당 벽 프리팹 1개만 배치, 높이는 프리팹 메시가 소유. `FaceCenter` + 약간의 랜덤 Y로 절벽이 안쪽 향하게. 인접 셀 중첩은 자연물이라 **오히려 유기적**(허용).

**천장**: `hasCeiling=false`면 `BuildCeiling` 스킵 → 열린 하늘. Forest/Abyss = false, 실내 = true.

**낙사 방지**: 천장 없는 방은 `CreateSafeFloor`(투명 바닥)와 외곽 벽으로 이미 막힘. Abyss의 `.`/`Pt`는 의도적 구멍이므로 예외.

---

### C. 빛 — **죽은 시스템 복구 + 숲 광원**

`RoomLightingConfig`(wallLightPrefab/centerLightPrefab/spacing/heightRatio/maxWallLights)는 코드는 살아있고 **데이터만 비었다.** 팔레트 .asset에 값을 채우면 `BuildRoomLights`가 즉시 동작.

**Forest 조명**:
- `centerLightPrefab` = **`AN_GodRays.prefab`**(참조 정상 확인됨) — 나뭇잎 사이 산광. 천장 없으니 중앙 상공에서 내리쬐게.
- `wallLightPrefab` = 은은한 앰비언트(반딧불 대용 파티클 or 약한 Point). 반딧불 프리팹은 없음 → 파티클 신규 or 생략.
- 씬 RenderSettings(스카이박스/포그/환경광)는 이미 챕터별 존재 → 방 조명이 얹히기만 하면 됨.

**Abyss 조명**: 아래에서 올라오는 발광(구멍 가장자리), 차갑고 낮은 키. `centerLightPrefab` 없이 `wallLightPrefab`만 or 전용 발광.

**성능**: `maxWallLights`로 실시간 조명 캡(현재 0=무제한). 큰 방 과부하 방지 위해 파일럿에서 실측 후 상한 설정.

---

### D. 프롭 — **DecorationCatalog 실사용**

`DecorationCatalog_Forest`(나무·덤불·버섯·꽃 6종)가 **복구 완료됐으나 CSV에 `d*` 토큰 0개**라 한 번도 안 쓰임. A(공간 문법)에서 `d*`를 뿌리면 자동 배치됨.
- 코드 코드/매핑: `t`=Fir_3, `p`=Fir_1, `n`=Broadleaf_3, `f`=Flowers, `l`=Bush_2, `m`=Mushrooms.
- Abyss용 카탈로그는 **없음** → 필요 시 신규(발광 크리스탈·유골 등). 파일럿 2차에서 판단.

## 4. 구현 순서 (각 단계 검증 포함)

```
1. 수직 프로필 구조 (안 A)      → verify: Forest 방이 절벽 벽 + 천장 없이 빌드되는지 (에디터 육안)
2. 팔레트 조명 데이터 채우기     → verify: BuildRoomLights가 GodRays/조명 실제 배치하는지 (로그+육안)
3. Forest 방 골격 8종 재저작    → verify: 린터 ERR 0 + 육안(형태 다양성)
4. d*/O 토큰 배치 (프롭·장애물)  → verify: 나무·바위 실제 스폰, 통행 가능
5. 바닥/벽 머티리얼 마감        → verify: 회색 Cube 0개
6. CDN 재업로드                → verify: 온라인 실행 반영
--- 여기까지 Forest 1차 완료, 플레이 확인 ---
7. Abyss 방 골격 + . /Pt 낙사   → verify: 낙사·복구 동작
8. Abyss 조명/에셋 마감         → verify: Ch1 후반이 전반과 명확히 다름
```

각 단계는 **컴파일 검증**(`refresh_unity`→`read_console`) + 육안 확인. 코드 변경은 1·2단계뿐, 나머지는 데이터.

## 5. 미결정 / 캘리브레이션 (구현 착수 전 확인)

1. **절벽 벽의 셀당 배치**: AN_Cliff_1이 3.5셀 폭 → 인접 셀마다 놓으면 중첩. (a) 셀마다 놓고 중첩 허용(유기적), (b) N셀마다 한 개 + 사이는 저벽, (c) 외곽 링만 절벽. → 파일럿에서 실측 후 결정 권장.
2. **벽 높이 수치**: Forest 절벽 실제 높이(현 5m). 카메라 앵글에서 답답하지 않은지.
3. **반딧불**: 신규 파티클 제작 vs 생략(GodRays+포그로 충분한지).
4. **Abyss 카탈로그**: 신규 장식 세트 만들지, 바위 재활용할지.
5. **팔레트 파일명**: 현재 Cave/Castle/Throne이 themeMatch(Lava/Sacred/Fortress)와 불일치. 이번 슬라이스에서 정리할지, 나중으로 미룰지.

## 6. 리스크

- **오브젝트 수**: 32×32 방 = GO 3천+. 절벽 단일형은 벽을 12층→1층으로 줄여 **오히려 감소**. 프롭은 증가 → LOD·`maxWallLights`로 관리.
- **CDN 이중 관리**: CSV 수정마다 프로젝트본+데스크탑 원본+CDN 3곳. 재업로드 누락 시 온라인 미반영.
- **협업(LEE)**: 보스 커스텀 아레나는 LEE 담당 — 건드리지 않음. 이 슬라이스는 절차 격자 방만.
- **Ch2~4 파급**: 수직 프로필(안 A)은 팔레트 단위라 Ch2~4에도 자동 적용 가능. 단 실내(Stacked+천장)는 별도 저작 필요.
```
