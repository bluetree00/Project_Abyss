# 유물 파츠·진화 설계 (보스 클리어 성장)

작성 2026-07-21. 관련 코드: `RelicPartEntry` · `RelicPartsDataManager` · `UI_RelicPartDraftPopup` · `GameRunBootstrapper.ShowRelicPartDraftAsync` · `PlayerLoadout.RelicPartIds`.
데이터: `RELIC_PARTS_DATA.csv` (데스크탑 "사용중 테이블").

> 이 문서는 **기획 확정본**이다. 파이프라인(데이터→드래프트→저장)은 이미 구현돼 있고, 이 문서는 남은 갭(효과 레이어·데이터)을 채우기 위한 설계 기준을 못 박는다.

---

## 1. 밸런스 철학 — 2층 분리

게임의 기본 난이도는 **약간 어려운 정도**로 유지한다. 영구 돌파력은 **각성**(수치 성장, 후속 시스템)이 담당하고, 유물 파츠는 **런 내 빌드 다양성**만 담당한다.

| 층 | 담당 | 지속 | 성격 |
|---|---|---|---|
| **유물 파츠** | 기능·메커니즘 변화 | 런 한정(매 런 리셋) | 작동 방식 변화 — **수치 강화 없음** |
| **각성** (후속) | 순수 수치 성장(공/방/체력 등) | 영구(계정 누적) | 장기 파워 — "점점 깰 수 있게" |

### 🔒 규율 원칙 (파츠 설계의 대전제)
- **파츠에 순수 수치 강화(공격력 %, 체력 % 등)를 넣지 않는다.** 그건 각성/무기 강화의 몫.
- 파츠는 "무엇이 일어나는가"를 바꾼다(화상 전염, 상시 정오…), "얼마나 세진다"를 바꾸지 않는다.
- 이 덕에 어떤 파츠 조합을 뽑아도 런이 거저 되지 않아 **기본 난이도가 보존**된다.

> "파츠"는 이 프로젝트에서 두 개다 — 혼동 주의.
> · **유물 파츠**(이 문서) = 유물 성장, 보스 드래프트.
> · **원거리 파츠** = 원거리 무기 강화(분열·관통), 재련소 탭2. **별개 시스템.**

## 2. 티어 구조 (현행 유지)

파츠는 두 티어로 나뉘고, 보스 클리어 시 **3택 드래프트**로 획득한다(택1 강제, 넘기기 없음 — 무료 성장이라).

| 티어 | part_kind | 성격 | 획득 시점 |
|---|---|---|---|
| **기능 파츠** (tier 1) | `effect` / `behavior` / `trigger` | **가산형** — 여러 개 쌓임 | 초반 보스들 |
| **코어 진화** (tier 3) | `core` | **분기형** — 갈림길 택1, 유물이 크게 변형 | 최종 직전 보스 (클라이맥스) |

→ **혼합 모델**: 기능은 쌓이고(가산), 진화(코어)는 방향을 가른다(분기). 런당 진화는 **1회**.

### 파츠 4종 정의 (수치 아님, 기능만)
| 종류 | 뜻 | 가웨인 예시 |
|---|---|---|
| `effect` (효과) | 새 상태이상·부가 판정 | 화상 전염 — 화상이 적→적으로 옮음 |
| `behavior` (행동) | Q·패시브 작동 방식 변화 | 정오 필드 화상 — 정오 진입 시 발밑 장판 |
| `trigger` (트리거) | 새 발동 조건 | (조건부 발동 추가) |
| **`core` (진화)** | 메커니즘 재편(방향 게이트) | 영원한 정오(황혼 제거·상시 정오) / 태양의 재앙(화상 연쇄 폭발) |

## 3. 레벨디자인 매핑 (챕터 = 진화 시점)

진화 시점은 코드가 `IsNextChapterFinal()`로 **챕터 수에 자동 연동**한다(A안 확정). 즉 "최종 직전 보스 = 진화, 최종 보스 = 승리(드래프트 없음)".

| | **완성 (최종 Ch4)** | **데모 (최종 Ch3 컷)** |
|---|---|---|
| Ch1 보스 | 기능 파츠 | 기능 파츠 |
| Ch2 보스 | 기능 파츠 | **◆ 코어 진화** |
| Ch3 보스 | **◆ 코어 진화** | 승리 (드래프트 없음) |
| Ch4 보스 | 승리 | — |
| 드래프트 횟수 | 기능 2 + 진화 1 | 기능 1 + 진화 1 |

**A안 채택 이유**: 데모(Ch3 컷)에서도 진화를 한 번 겪고(Ch2), 진화된 유물로 최종 보스(Ch3)를 싸우는 **온전한 루프**가 나온다. 완성으로 확장하면 진화가 자동으로 Ch3로 밀린다. 코드 무수정.

> 대안 B(진화를 절대 챕터 Ch3로 고정)는 데모에서 진화=최종 보상이 되어 써먹을 챕터가 없어 폐기.

## 4. 데이터 규모 목표

보스마다 3택이므로, 매 런 다르게 느끼려면 **뽑는 수보다 풀이 커야** 한다.

| 티어 | 유물당 최소 종수 | 근거 |
|---|---|---|
| 기능 파츠 (tier1) | **4~5종** | Ch1(+완성 Ch2)에서 3택 → 풀이 더 커야 반복감 없음 |
| 코어 진화 (tier3) | **2~3종** | 최소 2개라야 "갈림길(선택)"이 성립 |

유물 2종(가웨인·랜슬롯) 기준 총 **기능 8~10 + 코어 4~6 ≈ 12~16행**.
현재 CSV 19행이나 **가웨인 편중** → **랜슬롯 채우기가 데이터 작업의 핵심**.

## 6. 남은 구현 갭 (기획 확정 후 착수)

### 🔴 갭 1 — 파츠 효과 미구현 (핵심 작업량)
`loadout.RelicPartIds`를 **읽어 `effect_key`별 런타임 효과를 발동하는 코드가 0곳.** 현재는 id만 저장되고 게임플레이 영향 없음(`RelicPartEntry` 주석 "구현은 후속").
→ 서약/아이템 효과 팩토리 패턴을 참고해 `effect_key → 런타임 훅` 레이어를 만든다. **§1 규율(수치 금지) 준수.**

### 🟠 갭 2 — CSV 프로젝트 미반영
데이터가 데스크탑에만 있음. 로드는 CDN 우선인데 미업로드면 폴백도 없어 **후보 0 → 드래프트 스킵**.
→ CDN 업로드 + 프로젝트 폴백 복사본(아이템 데이터와 동일 패턴).

### 🟡 갭 3 — 랜슬롯 데이터 부족
§4 규모 목표 대비 랜슬롯 파츠 채우기.

## 8. 밸런스 시나리오 (진화 시)

> ⚠️ **함정: "수치 아님 ≠ 약함".** 진화(코어)는 쿨다운 제거·상시 발동 같은 **메커니즘 변화**라, 순수 수치 강화보다 실질 파워가 클 수 있다. 그래서 진화야말로 가장 신중히 튜닝해야 한다.

### 8.1 런 파워 커브 (데모 Ch3 기준, 각성 없음)

데모에는 영구 각성이 없다. 런 내 파워 원천은 **base + 무기 + 아이템 + 파츠 + 진화**뿐이다.

```
Ch1 입장 ── Ch1 보스 ──[기능 파츠]── Ch2 ── Ch2 보스 ──[◆진화]── Ch3 ── Ch3 최종보스
  baseline   첫 벽         +메커니즘     ↑아이템   진화 직전 벽   파워 스파이크   진화 캐리   피날레
```

- **Ch1 보스** = "약간 어려움"의 기준 앵커. **파츠 0개**로도 이길 수 있게(스킬로) 튜닝. 여기가 난이도 원점.
- **Ch2 보스** = 진화 직전 벽. "base + 기능 파츠 1 + 아이템"으로 튜닝.
- **Ch3 최종보스** = 피날레. **진화가 있다는 전제**로 튜닝(진화는 강제 드래프트라 최종보스는 항상 진화 후 전투).

### 8.2 진화 스파이크 크기 — 목표 밴드

**진화 실질 파워 상승은 ~20~40%를 목표**로 한다(2배 금지). 예시 계산 — 가웨인 **영원한 정오**(황혼 제거·상시 정오):

| | 정오 지속률 | 평균 DPS (정오 보너스 +60% 가정) |
|---|---|---|
| 진화 전 | ~50% (쿨다운 다운타임) | base × (1 + 0.5×0.6) = **base × 1.30** |
| 진화 후 | 100% | base × (1 + 0.6) = **base × 1.60** |

→ 진화만으로 **+23% 실질 DPS** + 다운타임 소멸(템포·생존 상승). "약간 어려움 → 깰 만함" 정도의 크기. **이 밴드를 넘기면(예: +100%) 최종보스가 무의미해진다.**

### 8.3 분기 = 특화지 파워가 아니다

코어 2종은 **누가 더 세냐가 아니라 어디에 강하냐**로 갈라야 한다:

| 진화 | 특화 | 최종보스(단일 대상) 상성 |
|---|---|---|
| 영원한 정오 | **단일 대상**(지속 화력) | 강함 |
| 태양의 재앙 (화상 전염·처치 폭발) | **군집**(연쇄 광역) | 약함(폭발 트리거 적음) |

→ **최종보스를 단일 대상 순수 DPS 체크로만 만들면 "영원한 정오"가 정답이 되어 분기가 죽는다.**
   최종보스에 **소환/쫄 페이즈나 광역 요구**를 섞어, "태양의 재앙"도 빛나는 구간을 준다. 그래야 진화 선택이 전략이 된다.

### 8.4 데모 특수성 — 각성 없는 피날레

**데모 Ch3 보스 ≠ 완성 Ch3 보스.**
- 완성: Ch3는 중간 지점, **각성 투자(영구 수치)** 를 등에 업고 싸운다 → 높게 튜닝 가능.
- 데모: Ch3가 피날레인데 **각성 0** → 첫 런에 base+파츠+진화+아이템+실력만으로 깰 수 있어야 한다.

→ **데모 Ch3 보스는 "첫 런에 클리어 가능한 피날레"로 낮춰 튜닝.** 완성 확장 시 각성 전제로 상향. (같은 챕터라도 데모/완성 튜닝값이 다르다.)

### 8.5 변수(variance) 관리 — 하한 보장

파츠는 3택 드래프트라 뽑기 편차가 있다. "약간 어려움"이 편차 밴드 전체에서 유지돼야 한다.

| 케이스 | 위험 | 대응 |
|---|---|---|
| 좋은 진화 + 좋은 아이템 | 최종보스 물렁 | 진화 상한(§8.2) + 아이템도 수치 인플레 억제 |
| 나쁜 진화(보스 상성 X) + 아이템 부족 | 최종보스 벽 | 진화 3택 중 **최소 1개는 범용**(상성 안 타는 것) 보장 + §8.3 혼합 페이즈로 만회 여지 |

→ **드래프트 후보 구성 규칙**: 코어 진화 3택에 "특화형"만 넣지 말고 **범용 1 + 특화 2** 구성. 나쁜 뽑기로 런이 막히는 걸 방지.

### 8.6 난이도 목표 밴드 (체크포인트)

| 지점 | 목표 클리어율(숙련자 기준) | 전제 파워 |
|---|---|---|
| Ch1 보스 | 높음(원점) | base only |
| Ch2 보스 | 중간(진화 직전 벽) | base + 기능 파츠 1 + 아이템 |
| Ch3 최종보스 | **약간 어려움**(피날레) | base + 파츠 + **진화** + 풀 아이템 |

핵심: **최종보스의 "약간 어려움"은 진화를 포함한 값**이다. 진화 없이 재보면 안 됨(강제 드래프트라 항상 있음).

### 8.7 회차 곡선 — "8회차 평균 클리어"

**타깃: 평균 플레이어가 최종보스를 ~8번째 트라이에 처음 클리어.**

> ⚠️ 이 곡선을 만드는 건 **각성(영구 수치)** 이지 파츠가 아니다. 파츠·진화는 매 런 리셋되므로 회차별 파워가 안 쌓인다. "점점 깰 수 있게"(각성)가 곧 회차 곡선의 엔진이다.

**두 축의 역할 분리:**
| 축 | 시간 스케일 | 회차 곡선 기여 |
|---|---|---|
| 파츠·진화 | 런 내(리셋) | **런 안의 편차**(이번 런이 좋냐 나쁘냐) |
| 각성 | 회차 누적(영구) | **회차별 상승**(8회차 곡선의 실체) |

**곡선 모델 (예시 수치):**
- 최종보스 클리어 요구 파워 `P_boss`. 각성 0인 런1 파워 `P_1` (= base+무기+파츠+아이템, 진화 포함).
- 매 런 각성으로 영구 파워 `Δ`씩 상승. `P_1 + 7×Δ + 실력성장 ≈ P_boss` → **Δ ≈ (P_boss − P_1 − 실력) / 7**.
- 즉 **런1에서는 파워+실력이 모자라 대체로 짐**, 회차마다 각성이 갭을 메워 ~8회차에 교차.

**각성 = 난이도 자동 조절 밸브 ("점점 깰 수 있게"의 정체):**
| 숙련도 | 클리어 회차 | 이유 |
|---|---|---|
| 숙련 | 3~5회 | 실력이 각성 부족을 상쇄 |
| **평균** | **~8회** | 타깃 |
| 저숙련 | 12회+ | 각성을 더 쌓아 파워로 실력을 상쇄 |

→ 각성이 **하한을 계속 끌어올려** 누구나 결국 이기게 한다. 실력은 회차를 앞당길 뿐. 이게 "약간 어려움"과 "점점 깰 수 있게"가 공존하는 방식이다.

**튜닝 레버 (8회차를 맞추는 손잡이):**
1. **각성 회당 파워 `Δ`** — 크면 회차↓. 8회차에 맞춰 조정.
2. **보스 요구 `P_boss`** — 런1과의 갭.
3. **각성 비용 곡선** — 초반 저렴(빠른 성취감) → 후반 체감. 초반 몇 회는 눈에 띄게 강해지게.
4. **실력 비중** — 8회 중 몇 회가 학습이고 몇 회가 파워인지.

### 8.8 데모 딜레마 (지금 결정 필요) 🔴

**데모(Ch3 컷)에는 각성이 없다 → 8회차 곡선의 엔진이 빠져 있다.** 각성 없이는 매 런 파워 상한이 동일해, "8회차에 강해져서 깬다"가 성립하지 않는다(순수 실력 벽만 남음). 게다가 로그라이트에서 **죽어도 영구 보상 0**이면 리트라이 동기가 약하다.

세 방향:

| 안 | 데모 구성 | 8회차 곡선 | 비용 |
|---|---|---|---|
| **A. 최소 각성 슬라이스** (추천) | 각성의 축소판(핵심 수치 몇 개 + 재화)만 데모에 포함 | ✅ 성립 | 각성 최소 구현 필요 |
| B. 순수 실력 벽 | 각성 없이 데모 = 실력만으로 ~8회 학습 | △ 학습곡선으로 근사 | 죽어도 보상 0 → 이탈 위험 |
| C. 데모는 낮게, 회차 무관 | 데모 최종보스를 첫 런에 깰 수준으로 낮춤 | ✗ (8회차 아님) | 데모가 쉬워져 "약간 어려움" 톤 상실 |

**추천 A** — 각성의 **핵심만 데모에 넣어** 회차 곡선을 실제로 돌린다. 죽음이 영구 보상으로 이어져 리트라이가 의미 있어지고, 완성으로 각성을 확장하면 곡선이 자연히 길어진다(8회 → 더 긴 엔드게임). 데모가 게임의 **핵심 루프(죽음→성장→재도전)** 를 온전히 보여준다.

> 즉 "8회차 평균"을 데모에서 실현하려면 **각성이 '나중'이 아니라 데모 범위로 당겨져야** 한다(최소 슬라이스라도). 이게 파츠 작업과 별개의 선결 과제다.
